# Project Overview

## 项目定位

这个项目是一个面向企业知识问答场景的 RAG 系统，目标不是只做一个“能回答问题”的 Demo，而是把 Java 后端工程能力和 RAG 算法链路放在同一条生产链路里一起落地。它既要支持知识库导入、切块、向量检索、意图路由、LLM 流式回答，也要在高并发下保持稳定、可观测和可回归。

## 核心链路

一次对话请求从 `RAGChatController` 进入后，会先经过全局排队限流，再进入 `RAGChatServiceImpl`。服务端会加载多轮对话记忆，执行问题重写与拆分，然后进行意图识别。对命中知识库的意图，系统会进入多通道检索链路；对系统能力型意图，会直接走 Prompt 模板或 MCP 工具链。最终，服务端把结构化上下文拼装给大模型，并通过 SSE 持续输出回答。

## 工程分层

- `bootstrap`
  承载控制器、业务服务、RAG 主流程和管理端接口。

- `framework`
  提供统一返回体、上下文、Trace、Web 组件和基础设施封装。

- `infra-ai`
  对接 Embedding、LLM、Rerank 等 AI 能力，支持模型路由与流式回调。

- `frontend`
  提供管理端和对话端页面，包括 dashboard、知识库管理、Trace 查询等。

## 为什么适合写简历

这个项目天然覆盖了两类最容易被面试官追问的数据：

1. Java 后端工程数据
比如 QPS、并发数、平均 RT、P95、错误率、慢请求比例、内存稳定性。

2. RAG 算法效果数据
比如 Top-3 文档命中率、无文档回复率、答案关键词覆盖率、意图路由命中情况。

如果你把这个项目量化好，就可以同时回答“你能不能写业务系统”和“你会不会把 AI 链路工程化”这两个问题。

# Resume Highlights

## 推荐亮点一

“设计双路检索与 Rerank 链路，结合问题重写与意图路由，在自建企业知识回归集上将 Top-3 文档命中率提升至 X%，答案关键词覆盖率提升至 X%。”

这条亮点适合回答：

- 你如何提升 RAG 召回率
- 为什么不是只做向量检索
- 你如何量化算法链路收益

## 推荐亮点二

“基于 Redis + Lua + ZSET 实现全局排队限流与 SSE 资源保护，在 X 并发压测下单节点稳定支撑 X QPS，平均 RT X ms，P95 X ms，测试期间无 OOM 和服务宕机。”

这条亮点适合回答：

- 你如何处理高并发
- 为什么 RAG 场景比普通接口更难限流
- 你在 Java 后端性能优化里做过什么

## 推荐亮点三

“搭建 RAG Trace 与 Dashboard 可观测体系，覆盖 rewrite、intent、retrieve、llm-routing 等关键节点，实时统计成功率、错误率、无文档回复率和延迟趋势，支持链路定位与离线回归。”

这条亮点适合回答：

- 你如何做线上观测
- 遇到回答异常时怎么排查
- 你如何证明系统稳定且持续可维护

## 面试深挖时的回答顺序

1. 先讲业务目标
   说明这是企业知识问答，不是普通聊天 Demo。

2. 再讲链路设计
   重写、意图、双路检索、Rerank、流式回答。

3. 再讲工程难点
   SSE、并发、限流、记忆、可观测。

4. 最后给数据
   Top-3 命中率、QPS、RT、P95、成功率、无文档回复率。

只要这四步顺下来，这个项目就会非常像一段“真的做过工程化落地”的经历，而不是单纯套壳调用大模型。

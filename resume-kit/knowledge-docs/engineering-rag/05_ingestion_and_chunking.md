# Ingestion And Chunking

## 文档导入链路

知识库管理支持文件上传和 URL 导入。上传后，系统会把文件先落到对象存储，再把文档记录写入数据库，然后触发异步切块任务。对切块成功的文档，会继续做向量化并写入 Milvus。这样把“文件存储”和“向量索引”分开，可以让后续重切块、重建索引、禁用文档这些动作更容易做。

## 切块策略

项目支持至少两类处理模式：

1. `chunk`
  直接按固定大小或结构感知策略切块。

2. `pipeline`
  把文档处理交给 ingestion pipeline，适合更复杂的数据清洗链路。

如果你要做简历演示，结构感知切块通常更适合，因为它更容易在问答里保持段落语义完整。

## 建议切块参数

对简历演示类知识库，可以优先用这一组参数：

- `targetChars = 900`
- `maxChars = 1200`
- `minChars = 400`
- `overlapChars = 120`

这样做的好处是：

- 不会把关键描述切得太碎
- 又能保证单个 Chunk 不至于过长
- 对结构化说明文档比较友好

## 导入后要检查什么

- 文档状态是不是 `success`
- 每篇文档是不是有合理的 `chunkCount`
- 搜索和问答是否能命中正确文档
- Trace 里 `resultChunkIds` 是否稳定命中目标文档

如果这些都正常，再去做回归评估和压测，拿到的指标才更可信。

# Retrieval Pipeline

## 双路检索设计

系统的知识检索不是单路向量召回，而是把“意图定向检索”和“全局向量兜底检索”组合起来。第一条链路会根据意图识别结果，把查询定向到命中的知识库和意图节点；第二条链路会在意图置信度不高或无明确意图时，做全局向量检索，避免因为意图误判导致漏召回。

## 问题重写与拆分

在进入检索前，系统会先做问题重写和子问题拆分。这样做的价值有两点：

1. 把口语化、上下文依赖较重的问题改写成更适合向量检索的表达。
2. 把复合问题拆成多个子问题，让每个子问题分别命中更清晰的意图和知识片段。

这一步对复杂企业知识问答尤其重要，因为真实用户往往会把多个意图混在一句话里。

## Rerank 放置位置

双路检索会先并行返回多个候选 Chunk，然后把结果汇总交给 Rerank 模型重排。Rerank 的价值不是简单再排序，而是把“语义相关但位置靠后”的片段重新拉回到前几位，提升最终喂给大模型的上下文质量。工程上一般更适合用 Top-N 命中率来描述它的收益，而不是只说“答案更准”。

## 建议统计的指标

- Top-3 文档命中率
  在自建测试集上，看前 3 个返回文档里是否命中至少 1 个目标文档。

- Top-5 文档命中率
  适合作为更宽松的召回观察指标。

- 答案关键词覆盖率
  作为终端回答准确率的保守代理指标。

- 无文档回复率
  用于衡量系统在真实场景下的召回下限。

## 简历表达方式

不要只写“设计了双路检索和 Rerank”，更好的写法是：

“设计双路检索与 Rerank 链路，结合问题重写与意图路由，在自建企业知识回归集上将 Top-3 文档命中率提升至 X%，答案关键词覆盖率提升至 X%。”
